# 01. 계획 (Planning)

> **검토 포인트** — "무엇을, 왜, 어떤 데이터로 풀지" 프로젝트의 목표·범위·작업 분해를 수집 이전에 어떻게 정의했는가.

데이터 수집·분석에 착수하기 전, 분석 목표 → 데이터 요구사항 → 일정/WBS 순서로 계획을 구체화했습니다. (CRISP-DM의 *비즈니스 이해*, SDLC의 *계획* 단계)

## 파일

| 파일 | 내용 |
|------|------|
| [`planning.md`](planning.md) | **계획 정본** — 로드맵·WBS 통합. 원안 → 실제 변경 이력 포함 |
| [`data_requirements.md`](data_requirements.md) | **데이터 요구사항 정의(DRD)** — 분석질문 ↔ 데이터 매핑, 대상 엔티티, 표본·품질 기준, 리스크 |
| `PostgreSQL 기반 데이터 수집·분석 프로젝트 로드맵.docx` | 전체 단계 로드맵 (변경이력 포함) |
| `WBS_핀테크 서비스 기획 4회차_코코넛사일로.xlsx` | 작업 분해 구조(WBS) — 일정·태스크 관리 |

## 다음 단계로의 연결

계획에서 정의한 분석 목표 → DRD로 구체화 → **[02. 수집](../02_수집_collection/)** 에서 ERD·스키마 설계와 멀티채널 수집으로 이어집니다.
