# 📑 데이터 요구사항 정의서 (DRD) — Kokkok EV

> **위치**: 계획(Phase 0 — WBS·로드맵·범위 정의) → **본 DRD(요구사항 분석)** → ERD·DB 스키마 설계 → 데이터 수집(Phase 2)
> **작성 맥락**: 수집 요구사항은 WBS 리서치/데이터수집 시트와 ERD에 **부분적으로 흩어져** 있었습니다. 본 문서는 이를 **하나의 정본 요구사항 정의서로 통합**하고, "사전에 정의한 요구 → 실제 수집 결과(충족/조정)"를 함께 기록합니다. 일부 요구는 수집 중 데이터로 검증·수정되었으며, 그 이력은 [README 회고](../README.md#-프로젝트-진행-기록--문제--시도--결과-발표-회고용)에 연결됩니다.
> **정본 수치 기준**: DB(Supabase) 실측 (2026-06).

---

## 1. 목적과 범위

**목적** — 라오스·베트남 EV 충전 서비스의 **실제 사용자 불만(VOC)을 정량화**하고, 그 근거로 충전 서비스 기능 우선순위·요금정책·시장 진입 전략을 도출하기 위해 *수집 전에* 필요한 데이터의 종류·양·품질·출처 기준을 정의한다.

**범위(In)** — EV 충전 앱 VOC, 모빌리티 슈퍼앱 경쟁 리뷰, 충전기 하드웨어·시장·정책 뉴스, 라오스 거시 공식 통계, 경쟁사 단가/IR.
**비범위(Out)** — 개인정보·결제정보, 비공개 운영 로그, 시장조사업체 유료 추정치(신뢰도 원칙상 배제). → §8.

## 2. 분석 질문 ↔ 필요 데이터 (요구 매핑)

> "이 질문에 답하려면 어떤 데이터가 반드시 있어야 하는가"를 먼저 정의 → 수집 대상 확정.

| # | 분석 질문 | 필요 데이터 | 대상 테이블 |
|---|----------|-----------|-----------|
| Q1 | 충전 앱 사용자의 **#1 불만**은 무엇인가 | 충전 앱 리뷰(다국어) + 감성·키워드 | `app_reviews` |
| Q2 | 불만이 **앱(SW)** 문제인가 **충전기(HW)** 문제인가 | 충전기 하드웨어·OCPP 뉴스 | `news_articles`(HW) |
| Q3 | 슈퍼앱은 **EV를 어떻게 통합**하는가 (경쟁) | 모빌리티 슈퍼앱 리뷰 | `superapp_reviews` |
| Q4 | 라오스 **시장·정책·경쟁 구도**는 (진입 근거) | 시장·정책 뉴스 + SoV | `news_articles` |
| Q5 | **실사용 맥락·여정**은 어떠한가 | 유튜브 영상 자막·댓글 | `youtube_*` |
| Q6 | **요금·시장 규모·거시 환경**의 정량 근거는 | 공식 통계·경쟁사 단가/IR | `reference_stats` |

## 5. 데이터 품질·완전성 기준

- **최소 표본**: 정성 카테고리화의 유의성을 위해 분석 단위(앱)당 **부정 리뷰 ≥ 약 300건**. 미달 시 단독 분석 불가 → 비교군 대체.
- **출처 신뢰도 등급**: `official`(정부·기업 공식) > `igo`(IEA·World Bank 등) > `secondary`. **시장조사업체 추정치는 배제**(검증 불가). 추정치를 임시 사용할 경우 **출처·검증 여부 표기 필수**.
- **전처리 완전성**: `lang_detected` → `sentiment_label/score` → `keyword_category`(+ 충전 도메인은 `keyword_domain` 2계층) 순으로 컬럼 충족.
- **중복·결측**: 앱 ID·video_id·(category,entity,metric,period) 유니크 제약으로 중복 차단. 라오어 단문은 언어감지 오분류 가능 → 한계로 명시.

## 6. 사전 식별 제약·리스크 → 실제 결과 (회고)

> DRD가 *사전에* 잡을 수 있었던 리스크와, 실제 수집에서 어떻게 충족/조정됐는지.

| 사전 리스크(요구 기준) | 실제 결과 | 조정 |
|----------------------|----------|------|
| 앱당 최소 표본 미확보 가능성 | **LOCA EV 7건**(라오스 리뷰 문화 부재) | 태국 비교군 3종 추가 |
| 동일 앱 중복 수집 | Green SM = V-Green **동일 ID** | `MUL` 통합 처리 |
| VOC와 시장정보 혼재 | 뉴스가 VOC와 목적 상이 | `news_articles` **분리 설계** |
| API 페이지네이션 한도 | Google Play 조합당 ~2~3천 | 언어·국가 5조합 분할 |
| 라오스 1차 데이터 공백 | 대용 표본 의존 | 라오스 SoV 타겟 수집 + 공식통계 보강 |

> ⚠️ 단, **하드웨어 뉴스·슈퍼앱 리뷰 추가**는 분석 중 새로 생긴 가설(Q2·Q3)에서 파생 — DRD로 완전히 선제할 수 없는 **탐색적 분석의 정상 특성**. DRD는 이를 "데이터 소스 × 분석질문" 매트릭스(§2)로 *검토하게* 만드는 장치다.

## 8. 비범위 (Out of Scope)

- 개인정보·결제정보·계정 자격증명 — 수집 금지.
- 비공개 운영 로그·내부 충전 세션 데이터 — 접근 불가(가정·시나리오로 대체).
- 시장조사업체 유료 추정치 — 신뢰도 원칙상 배제.
- Instagram 댓글 본문·작성자 — Graph API 제약으로 보류(B안).
